# 정답 라벨 지침 (v1, 2026-10-30)

> DESIGN.md 12.1. 이 문서는 **라벨을 달기 전에 고정**한다. 바꾸면 버전을 올리고, 이미 단 라벨은 옛 버전으로 남긴다.

## 1. 무엇을 라벨하나

- **단위**: (정정, 필드). 정정은 한 사업의 이전 버전 → 이후 버전 한 쌍이다.
- **필드**: 마감일(`deadline`), 지원 금액(`amount`), 신청 자격(`eligibility_rules`), 제출 서류(`required_documents`), 문의처(`contact`). 한 정정마다 다섯 필드 모두에 라벨을 단다.
- **엔진 결과를 보기 전에** 단다. 라벨 화면은 엔진의 조각 비교를 보여 주지 않는다. API 응답 값 비교, 본문 비교, 첨부 원본만 본다.
- 화면: `uv run python scripts/label.py` → http://127.0.0.1:8001
- 순서(2026-11-25 추가, 지침 내용은 그대로 v1): `scripts/eval.py --focus-out data/labels/focus-dev.json`이 개발 세트 정정을 "방식끼리 판단이 갈린 정정 → 나머지" 순서로 적고, 화면은 그 순서로 먼저 보여 주며 저장하면 다음 정정으로 넘어간다. 파일에는 버전 ID와 묶음만 있고 어느 필드가 갈렸는지, 어느 방식이 무엇을 말했는지는 없다. 갈린 곳만 달면 두 방식 중 누가 맞는지는 알지만 전체 정확도는 모르므로, 개발 세트 30건을 모두 단다.

## 2. 상태 네 가지

| 상태 | 언제 | 예 |
|---|---|---|
| 바뀜 (`changed`) | 정규화한 값이 달라졌다 | 마감 11/07 → 11/14, 업력 7년 → 5년, 서류 하나 추가 |
| 안 바뀜 (`unchanged`) | 값도 문구도 같다 | |
| 문구만 바뀜 (`wording_only`) | 문구는 달라졌지만 **정규화한 값이 같다** | "11월 7일(금)" → "2026. 11. 7.", "3천만원" → "30,000,000원", 같은 서류의 표 순서만 바뀜 |
| 필드 없음 (`absent`) | 두 버전 모두 그 정보가 없다 | 문의처를 적지 않은 공고 |

- 한쪽에만 있으면(새로 생김, 없어짐) **바뀜**이다. 이전·이후 값 중 없는 쪽은 비운다.
- 확신이 없으면 메모에 이유를 적고, 가장 가까운 상태를 고른다. 메모가 있는 라벨은 나중에 다시 본다.

## 3. 값 정규화

이전·이후 값 칸에는 아래 형식으로 적는다. 원문을 길게 옮기지 않는다.

| 필드 | 형식 | 예 |
|---|---|---|
| 마감일 | `YYYY-MM-DD` 또는 `YYYY-MM-DD HH:MM` (24시간) | `2026-11-14 18:00` |
| 지원 금액 | 기업당 최대 금액, 원 단위 정수, 쉼표 없음 | `30000000` |
| 신청 자격 | 바뀐 조건만 `속성 연산자 값`으로, 여러 개면 `;` | `업력 <= 60개월; 대표자 나이 <= 39` |
| 제출 서류 | 서류 이름을 가나다순으로 `;` | `사업계획서; 사업자등록증 사본` |
| 문의처 | 전화번호는 `000-0000-0000`, 기관명 없이 | `051-123-4567` |

- 신청 자격의 속성 이름: 업력(개월), 대표자 나이, 소재지, 업종, 사업자 형태, 매출(원), 상시 근로자 수, 예비 창업자, 여성기업, 재창업. 사전에 없는 조건은 짧은 말로 쓴다("중복 수혜 제외").
- "N년 이내"는 개월로 바꾼다(7년 이내 → `업력 <= 84개월`).
- 날짜에 요일·마침표·공백이 달라도 같은 날이면 같은 값이다.

## 4. 근거 위치와 어디서 보이나

- **근거 위치**: 정답을 찾은 곳을 짧게. `공고문.hwp 2쪽 표1 신청자격`, `본문 셋째 문단`, `API reqstBeginEndDe`. 원문 문장은 붙이지 않는다(공개할 때 위치만 남긴다).
- **어디서 보이나**: 변경을 처음 확인할 수 있는 곳 하나.
  - `API 메타`: API 응답의 구조화된 값(접수 기간 등)만 봐도 알 수 있다.
  - `본문`: API 본문(사업 개요) 글에서 보인다.
  - `첨부`: 첨부 파일을 열어야만 보인다.
- 여러 곳에서 보이면 위 순서(API 메타 → 본문 → 첨부)에서 앞에 있는 것을 고른다.

## 5. 2차 라벨과 일치도

- 1차 라벨을 단 지 **7일 이상** 지난 정정 중 무작위 **30%**를 다시 단다. 화면의 `2차 라벨`에 나오고, 1차 답은 보이지 않는다.
- 일치도는 필드별 상태로 비율과 Cohen's kappa를 낸다(화면의 `일치도`). 가능하면 두 번째 사람이 `--labeler` 이름을 바꿔 같은 30%를 단다.

## 6. 공개

원문은 공개하지 않는다. 공개 산출물은 사업·버전 ID, 첨부 내용 해시, 라벨(상태·정규화 값·위치·어디서 보이나)과 생성 스크립트뿐이다(기업마당 공공누리 3유형, K-Startup 약관).

## 7. AI 라벨과 사람 확인 (2026-11-25 추가, 지침 내용은 그대로 v1)

- **누가**: 개발 세트 30건을 Claude가 1차로 달았다. `labeler=claude`로 저장해 사람 라벨(`me`)과 섞지 않는다. 메모 앞에는 `[claude]`를 붙였다.
- **무엇을 보고**: `scripts/label_packets.py`가 만든 자료 묶음을 봤다.
  - API 값 비교
  - 본문과 첨부를 합친 낱말 단위 비교. 같은 공고문이 PDF와 HWP로 함께 붙은 경우 겹친 줄은 한 번만 넣었다.
  - 이후 판에서 필드별 낱말을 뽑은 발췌
  - 엔진의 조각 비교는 보지 않았다.
- **한계**:
  - 첨부는 원본 파일이 아니라 우리 파서가 뽑은 글이다. 파서가 틀리면 라벨도 틀린다. 다만 모든 방식이 같은 파서 결과를 읽으므로 방식끼리 비교하는 데는 공정하다.
  - 라벨러는 어느 정정의 어느 필드에서 방식이 갈렸는지는 이미 알았다. 어느 방식이 무엇을 말했는지는 몰랐다.
- **사람 판정 (2026-11-25 사용자 결정)**: 사람은 Claude가 애매하다고 표시한 칸만 판정한다. 판정은 `labeler=me`로 남기고, 채점은 `--labeler claude --override me`로 AI 라벨을 사람 판정으로 덮어써서 한다. 첫 판정은 5칸이다(05·06 금액, 12 마감, 27 마감·서류).
- **무작위 확인(선택)**:
  - `uv run python scripts/label.py --check-against claude`를 실행하면 Claude가 단 정정 가운데 30%(올림, 시드 고정)가 "확인" 묶음으로 먼저 보인다. Claude의 답은 보이지 않는다.
  - 사람이 다 달면 `일치도` 화면에 사람 대 Claude의 일치율, kappa, 상태가 다른 곳 목록이 나온다.
  - 발표에는 AI 라벨로 잰 숫자를 이 일치도와 함께 쓴다.
  - 다른 곳은 사람이 다시 보고 정한다. 정한 결과는 사람 라벨로 남는다.
- **채점**: `uv run python scripts/eval.py --labeler claude`. 사람 라벨로 채점하려면 `--labeler me`(기본값)를 쓴다.

## 8. 시험 세트 (2026-11-29 추가, 지침 내용은 그대로 v1)

- **누가·언제**: 시험 세트 28건(사업 26개)을 Claude가 달았다(`labeler=claude`). **어떤 방식도 시험 세트에서 돌리기 전에** 달았다. 순서 파일(`data/labels/focus-test.json`)은 모두 `rest` 묶음이라, 어디서 방식이 갈렸는지도 몰랐다(개발 세트보다 더 가렸다).
- **무엇을 보고**: 7장과 같은 자료 묶음(`scripts/label_packets.py <폴더> --focus data/labels/focus-test.json`). 묶음이 잘린 곳은 이전·이후 판 전체 글에서 낱말로 찾아 확인했다(파서 출력, 엔진 비교는 보지 않음).
- **개발 세트의 사람 판정을 그대로 따랐다**: 이후 판이 더 이른 원 공고로 바뀌어도 글자대로 비교한다. 서류 이름이 같고 수량·서식 머리표만 다르면 같은 서류다. 요약에 옮겨 적기만 한 것은 문구만 바뀜이다.
- **사람 판정**: Claude가 애매하다고 표시한 13칸을 사람이 봤고 모두 동의했다(`labeler=me`, 메모 `[사람 판정] Claude 판단에 동의`). 채점은 개발 세트와 같이 `--labeler claude --override me`.
