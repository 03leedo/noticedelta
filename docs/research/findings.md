# 발표용 성과 기록

연구 질문(DESIGN 3장)과 그때그때 던진 질문에 대해 **숫자로 답한 것**만 모은다. 발표 자료는 여기서 꺼내 쓴다.
한 건의 모양: 질문 → 한 줄 답(슬라이드 제목감) → 숫자 → 어떻게 쟀나(다시 재는 명령) → 한계.
자세한 기록은 각 줄의 출처 문서에 있다.

## 한눈에

| # | 한 줄 답 | 핵심 숫자 | 날짜 |
|---|---|---|---|
| F1 | 정정의 39%는 API 메타로 안 보인다 | 조각이 바뀐 정정 49건 중 19건은 접수 기간(메타)이 그대로 | 11/16 |
| F2 | 첨부 파싱은 한국 공공 문서에서도 된다 | 첨부 119개 중 112개(94%), HWP·HWPX 70개 전부 | 10/19 |
| F3 | 개인정보를 가렸다 되돌려도 원문이 깨지지 않는다 | 조각 84.7만 개 전수, 되돌림 불일치 0, 인젝션 오탐 0 | 11/16 |
| F4 | **변경 영향 엔진은 전체 재추출보다 입력 토큰을 86% 덜 쓴다** | 30건: B2 386,331 → 엔진 52,771 입력 토큰 | 11/25 |
| F5 | 프롬프트 토큰의 절반 가까이는 내용이 아니라 조각 ID였다 | 추출 호출 60개 회귀 분석: 입력 토큰의 약 48% | 11/25 |
| F6 | 무료 학교 모델은 "형식을 지켜 달라"보다 받는 쪽의 관대함이 효과가 크다 | 자격 규칙 통과 48% → 90% | 11/24 |

## F1. 정정의 39%는 API 메타로 안 보인다 (RQ1의 배경)

- **질문**: 공식 API가 주는 구조화 값(접수 기간)만 비교해도 정정을 잡을 수 있나?
- **답**: 아니다. 조각이 실제로 바뀐 정정 49건(사업 48개) 가운데 30건만 API의 접수 기간이 바뀌었고, 19건(39%)은 본문·첨부에서만 바뀌었다.
- **어떻게**: `make eval`의 B0 줄과 입력 크기 표(LLM 없음). [eval.md](eval.md)
- **한계**: 30건 안에도 메타로 안 보이는 다른 변경이 함께 있을 수 있다(사람 라벨이 있어야 안다).

## F2. 첨부 파싱 94% (진행 판단의 근거)

- **질문**: HWP·HWPX·PDF가 섞인 공고 첨부를 기계가 읽을 수 있나?
- **답**: 첨부 119개 중 112개(94%). HWP·HWPX 70개는 전부, 실패 7개는 모두 글자 층이 없는 PDF(스캔본 6, 깨진 글꼴 1).
- **어떻게**: 파서 비교(kordoc 대 hwp-hwpx-parser). [parsers.md](parsers.md)

## F3. 개인정보 가리기와 인젝션 탐지 (하네스)

- **질문**: LLM에 보내기 전에 전화·이메일 등을 가렸다가 답에서 되돌리면 원문이 망가지지 않나? 실제 공고에서 인젝션 탐지가 오탐을 내나?
- **답**: 조각 847,174개 전수에서 되돌린 결과가 원문과 다른 조각 0개, 인젝션 의심 줄 0개.
- **어떻게**: `uv run python scripts/harness_scan.py`. [harness.md](harness.md)
- **한계**: 인젝션 탐지의 재현율은 직접 만든 공격 세트로만 쟀다(실제 공고에는 심은 지시가 없다고 본다).

## F4. 변경 영향 엔진은 전체 재추출보다 입력 토큰을 86% 덜 쓴다 (RQ1, 첫 실측)

- **질문**: 바뀐 조각과 영향받은 필드만 다시 묻는 엔진은 전체를 다시 뽑는 방식(B2)과 바뀐 조각만 LLM에게 판단시키는 방식(B3)에 비해 토큰을 얼마나 쓰나?
- **답**: 정정 30건에서 입력 토큰 B2 386,331 · B3 162,225 · **엔진 52,771**. 엔진은 B2의 13.7%, B3의 32.5%. 출력까지 더하면 B2 410,967 · B3 166,767 · 엔진 67,030(B2의 16.3%).

  | 방식 | LLM 호출 | 입력 토큰 | 출력 토큰 | "바뀌었다"고 본 정정 |
  |---|---|---|---|---|
  | B0 메타 비교 | 0 | 0 | 0 | 22 |
  | B2 전체 재추출 | 30 | 386,331 | 24,636 | 30 |
  | B3 바뀐 조각만 LLM에 | 30 | 162,225 | 4,542 | 25 |
  | **변경 영향 엔진** | 29 | **52,771** | 14,259 | 27 |

- **어떻게**: 부산대 피클 학교 모델 `pickle-general`(무료), 추출 틀 v1, 개발 세트. 녹화본으로 비용 없이 다시 낸다: `make eval`. 처음 측정은 `uv run python scripts/eval.py --provider pickle --mode replay_or_live --budget 250000`.
- **한계**: **정확도는 아직 모른다**(사람 라벨 0건). "바뀌었다"고 본 수가 맞는지는 라벨이 있어야 가른다. 필드별로 보면 B2는 자격 규칙이 30건 중 27건에서 "바뀌었다"고 해서, 같은 글을 다시 뽑을 때 규칙의 모양이 흔들리는 잡음일 가능성이 크다(F8에서 잰다). 엔진과 B2가 다르게 본 (정정, 필드) 41건은 라벨을 먼저 달 목록이다.

## F5. 프롬프트 토큰의 절반 가까이는 조각 ID였다

- **질문**: 학교 모델 하루 한도 안에서 더 많이 재려면 어디를 줄여야 하나?
- **답**: 추출 프롬프트는 조각마다 `[833c25ad4b0b] 원문`처럼 12자리 ID를 붙인다. 녹화본 60개의 실제 입력 토큰을 프롬프트 부분별 글자 수로 회귀하면(중앙 오차 2.7%) **입력 토큰의 약 48%가 ID**였다. 학교 모델(Qwen 계열)은 숫자를 한 자리씩 토큰으로 나누는 것으로 알려져 있어 16진수 ID가 특히 비싸다. 게다가 조각의 66%가 표 칸이고 15%는 빈 칸이라, ID만 있고 내용이 없는 줄이 많았다.
- **고친 것**: 추출 틀 v2. 요청 안에서만 쓰는 짧은 번호(`[1] 원문`)를 붙이고 빈 조각은 뺀다. 답의 번호는 lineage_id로 되돌리므로 엔진·인용 검증·저장은 그대로다. 글자 수로는 24% 준다(개발 세트 첫 판 30개).
- **실측**: (이어서 잰다) 같은 공고 30개에 v1과 v2를 돌린 입력 토큰과 값 일치.
- **어떻게**: 분석은 녹화본만(LLM 호출 없음). 비교는 `uv run python scripts/template_ab.py --provider pickle --limit 30`.

## F6. 무료 학교 모델은 받는 쪽을 고쳐서 쓴다

- **질문**: 유료 API 없이 학교 무료 모델로 연구 측정이 되나?
- **답**: 된다. 다만 모델의 출력 모양이 엉성하다. 근거 없는 필드를 빼라고 해도 `null`로 준다(20%), `value_json`이 JSON이 아니다(4%), 자격 규칙의 `manual` 칸에 원문 문자열을 그대로 넣는다. 받는 쪽을 고쳐(타입별 모양 맞추기, 문자열 manual 받기) **자격 규칙 검사 통과 48% → 90%**.
- **어떻게**: 녹화본 90개 분석. [eval.md](eval.md)

## F7. 무료 모델의 하루 한도 = 평가 한 바퀴 → 미리 세고 예산을 건다

- **질문**: 하루 토큰 한도(약 100만)가 있는 무료 모델로 측정을 어떻게 끝까지 하나?
- **답**: 평가 한 바퀴(호출 90번)가 입력 99.7만 토큰으로 하루 한도를 다 써서 엔진 측정이 잘렸다. 그래서 (1) 보내기 전에 녹화본에 없는 호출만 골라 크기를 세는 "미리 세기", (2) 넘을 호출을 보내기 전에 막는 토큰 예산을 게이트웨이에 넣었다. 다음 날 엔진 측정은 미리 센 값(입력 12.9만)대로 실제 12.8만(입력+출력)을 쓰고 끝났다.
- **어떻게**: `uv run python scripts/eval.py --provider pickle --plan`, `--budget N`. 같은 요청은 녹화본으로 다시 쓰므로 두 번 내지 않는다.
- **플랫폼으로서의 뜻**: 앱마다 LLM 예산을 두는 설계(app-spec 9장)의 첫 부품이다. 남의 앱을 돌리는 플랫폼이라면 "이번 실행이 얼마 드는지 먼저 보여 주기"가 기본이어야 한다.

## F8. 잡음 바닥 (이어서 잰다)

- **어떻게**: `uv run python scripts/template_ab.py --provider pickle --limit 15 --noise`.
