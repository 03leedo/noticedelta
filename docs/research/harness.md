# 하네스 1차 실측 (2026-11-16)

LLM 호출 앞뒤에 끼우는 단계(ARCHITECTURE 3.2)의 첫 구현과, LLM 없이 잴 수 있는 것을 잰 기록.
코드는 `src/noticedelta/llm/harness.py`, 다시 재려면 `uv run python scripts/harness_scan.py`.

## 무엇을 만들었나

| 하네스 | 하는 일 | 방식 |
|---|---|---|
| 개인정보 가리기 (`PIIMask`) | 주민등록번호·사업자등록번호·전화번호·이메일을 `[[PHONE_1]]` 같은 자리표시로 바꿔 보내고, 응답에서 원래 값으로 되돌린다 | 정규식 |
| 인젝션 탐지 (`InjectionGuard`) | 입력을 줄 단위로 보고, 모델에게 내리는 지시로 보이는 줄을 가리거나(기본) 기록만 하거나 호출을 막는다 | 규칙 6개. 강한 규칙 하나 또는 약한 규칙 둘 이상일 때만 의심 |

게이트웨이는 하네스를 거친 요청으로 녹화본의 키와 내용을 만든다. 그래서 가린 값은 모델에도 녹화본에도 가지 않는다.
앱 설정의 민감도 등급이 기본 하네스를 고른다(`for_sensitivity`): 공개 문서는 인젝션 탐지만, 사용자 정보가 섞이면 가리기까지.

## 실제 공고 조각으로 잰 것

대상: 지금까지 모은 공고 조각 847,174개, 서로 다른 글 294,314개.

| 항목 | 결과 |
|---|---|
| 개인정보 형식이 든 조각 | 8,587개 (2.9%) |
| 가려지는 값 | 전화 7,385 · 이메일 3,839 · 사업자등록번호 25 · 주민등록번호 형식 4 |
| 가렸다가 되돌렸을 때 원문과 다른 조각 | **0개** (전수 확인) |
| 인젝션 의심으로 잡힌 줄 | **0개** (실제 공고에는 심은 지시가 없다고 보면 오탐 0) |
| 약한 규칙 하나만 걸려 넘어간 줄 | 3개 (모델에게 말하는 꼴 2, 출력 지정 꼴 1) |

- 공고의 전화·이메일은 대부분 기관 문의처라 공개 정보다. 여기서 본 것은 "가려도 추출이 깨지지 않는가"이다. 문의처 추출을 가린 채로 돌려도 응답의 자리표시가 원래 값으로 돌아오고 인용 검증을 통과한다(`tests/test_harness.py`).
- 주민등록번호 형식 4건은 내용을 확인하지 않았다(서식 예시일 수 있다).

## 직접 만든 세트로 잰 것

심은 지시문 30개와, 공고에 흔하지만 지시문이 아닌 문장 15개(`tests/test_harness.py`).

| 세트 | 결과 |
|---|---|
| 걸리는 낱말이 있는 지시문 26개 | 26개 탐지 |
| 돌려 말한 지시문 4개 (낱말 없이 뜻만, 영어 완곡 표현, base64) | 0개 탐지 |
| 지시문이 아닌 문장 15개 | 0개 오탐 |

## 한계 (이 숫자를 읽는 법)

- 세트를 만든 사람과 규칙을 만든 사람이 같다. 탐지 26/30은 "아는 꼴은 잡는다"는 뜻이지 탐지율이 87%라는 뜻이 아니다. 공개 세트(AgentDojo 등)와 남이 만든 공격으로 다시 재야 한다(RQ9).
- 규칙 기반은 표현을 바꾸면 피한다. 구조적인 방어는 능력 분리다: 추출 LLM에는 도구도 민감 데이터도 없고, 받은 값은 인용 검증을 거친다. 이 하네스는 그 위의 한 겹이다.
- 사람 이름·주소는 가리지 못한다. 형식이 있는 값만 가린다.
- 오탐 0은 지원사업 공고에서의 결과다. 다른 도메인(예: AI 사용 지침 문서)은 다시 재야 한다.
- 가린 채로 추출했을 때 **정확도가 얼마나 떨어지는지**는 LLM을 불러야 잴 수 있다. 키가 오면 5번 실측과 함께 켬/끔으로 비교한다.
