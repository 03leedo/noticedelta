변경 전 값까지 웹 본문에 적힌 사례는 #14 하나입니다. 연장 공고 12건 가운데 원래 마감일을 본문에 적은 곳은 없었습니다. #10은 기업마당 두 수정본의 신청기간을 비교해 알아냈고, #25는 원공고 미러 페이지와 비교해 알아냈습니다.

### 원공고와 연결되는 방식
- **기업마당**: 수정할 때마다 **새 pblancId**가 생깁니다(예: 예창패 119019 → 119859, TIPS 117859 → 119754, 모두의창업 119979 → 120873). 원공고는 닫히고 **"조기마감 사유: 수정공고 업로드" / "수정 공고 게시"** 문구가 붙습니다(#6, 11, 12, 13에서 확인). 새 글에서 원공고로 가는 링크는 보이지 않았습니다.
- **K-Startup**: 같은 **pbancSn을 그대로 두고 덮어쓰는 경우**가 많습니다. 등록일은 원래 날짜로 남고, 제목에 "수정"이 붙고, 본문에 "YYYY.MM.DD.-신청기한연장" 같은 한 줄 이력이 추가됩니다(#9, 10, 18, 24). 반대로 **새 pbancSn으로 다시 올리는 경우**도 있습니다(#25 강원BRIDGE 연장. #13은 공고번호와 등록일이 바뀌어 새 글로 추정).
- **제목 표기가 제각각입니다**: "수정 공고", "수정공고", "(수정)", "(수정공고)", "수정(2차)", "정정 공고", "연장공고", "(연장)", "(모집연장)", "(기간연장)", "(접수연장)", "수정 연장". 이번 표본(2025~26)에서는 **"[정정]" 접두어를 쓴 사례가 없었고**, 표기 위치도 앞·중간·끝이 섞여 있습니다. 중앙부처 사업은 대부분 "수정"을 쓰고 "정정"은 드뭅니다.
- **공고번호가 바뀝니다**: 수정본이 새 공고번호를 받는 경우가 있습니다(208 → 275호, 233 → 296호). 본문에 원공고 번호를 적은 경우는 #6, 13에서만 확인했습니다.

## 3. 자동 변경 탐지 시스템에 주는 시사점
1. **본문에 적힌 "변경 전/후"에 의존하면 안 됩니다.** 전/후 대비가 본문에 있는 건 약 4%뿐이고, 68%는 제목에만 수정 표시가 있습니다. 시스템이 직접 **이전 버전을 보관(스냅샷)하고 비교(diff)**해야 합니다. 마감일, 신청기간, 자격요건, 지원금액, 제출서류 같은 핵심 필드를 구조화해 저장하고 버전마다 비교하는 방식이 필요합니다.
2. **진짜 내용은 첨부파일 안에 있습니다.** "6p 수정 확인"처럼 공고문 PDF/HWP 안의 바뀐 쪽만 가리키는 경우가 많습니다. 첨부파일 해시(파일명·크기·내용)를 추적하고, HWP/HWPX/PDF를 텍스트로 뽑아 문단 단위로 비교해야 합니다.
3. **두 포털을 같은 방식으로 처리할 수 없습니다.** K-Startup은 같은 ID를 덮어쓰므로 **같은 URL을 주기적으로 다시 수집**해야 놓치지 않습니다. 기업마당은 새 ID로 올라오므로 **새 글을 원공고와 짝짓는 작업(엔터티 해소)**이 필요합니다. 제목을 정규화한 뒤("수정/정정/연장/(n차)" 제거) 기관·사업명·공고번호·연도로 묶고, "조기마감 사유: 수정공고" 신호를 함께 쓰면 됩니다.
4. **한 사업이 여러 번, 여러 채널에서 수정됩니다.** 예창패 2026은 원공고 1번과 수정 2번이 기업마당 ID 2개, K-Startup ID 1개, 대학·지역 미러로 퍼졌습니다. **사업 단위 버전 체인**(v0 → v1 → v2)과 채널 간 중복 제거가 필요합니다.
5. **가장 흔한 변경은 마감 연장(약 43%)입니다.** 신청기간 필드 비교만으로도 상당수를 잡을 수 있지만, 이전 마감일을 알려면 이전 스냅샷이 꼭 있어야 합니다. 원공고가 이미 닫혀 내려간 뒤에 수집을 시작하면 복원할 수 없습니다.
6. **자격요건 변경은 문장 수준의 작은 차이입니다**(예: "단순 참관 포함" → "단순 참관, 시찰 제외"). 사용자 답변에 미치는 영향이 커서, 조항 단위로 비교하고 영향도를 분류해 알려야 합니다(자격 > 서류 > 일정).
7. **제목 키워드 사전**(수정|정정|변경|연장|재공고|추가모집|(n차))과 "조기마감 사유" 같은 메타 필드는 **변경이 있는지 알려 주는 신호**로만 쓰고, 무엇이 바뀌었는지는 비교(diff)로 확정하는 2단계 구조를 권장합니다.
