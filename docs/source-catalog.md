| 항목 | 내용 |
|---|---|

## 0. 한 줄

**출처마다 "어디서, 어떻게 가져오고, 무엇을 무시해야 하는지"를 적은 한 장.** 앱은 "무엇을 지켜볼지"를 적고, 카탈로그는 "그걸 어떻게 가져오는지"를 맡는다. 계속 지켜보는 일에만 쓴다(한 번 보고 끝나는 문서 비교는 카탈로그가 필요 없다).

카탈로그가 쓰이는 때: 가져올 때, "바뀌었다"를 판단할 때(무시할 값, 같은 항목 묶기, 출처가 정리해 주는 값), 앱을 만들고 검증할 때, 과거 기록으로 미리 돌려 볼 때, 여러 앱이 한 번의 수집을 나눠 쓸 때, 원문을 얼마나 보여 줄지 정할 때.

## 1. 누가 쓰나: 에이전트가 쓰고 사람이 확인한다

플랫폼을 쓰는 쪽은 대부분 에이전트다(비전공자의 에이전트, 개발자의 Claude Code). 사람에게 "글 목록의 CSS 선택자", "항목 ID 키"를 채우게 하는 양식은 비전공자가 쓸 수 없다. 그래서 일을 이렇게 나눈다.

| 누가 | 하는 일 |
|---|---|
| **사람** | 어디를 지켜볼지 말한다(주소나 사이트 이름) · 미리보기가 맞는지 확인한다 · 이용 조건에 동의한다 |
| **에이전트** | 플랫폼이 낸 초안 가운데 고르고, 틀리면 고친다 |
| **플랫폼** | 주소를 한 번 받아 보고 종류와 목록 위치를 먼저 제안한다 · 검증한다 · 안전 장치를 건다 · 사람에게 보여 줄 문장을 만든다 |

**에이전트가 쓰기 좋게 만드는 원칙**
- **스스로 설명한다**: 출처 목록에 키마다 설명과 예시 값, 갱신 빈도, 기록 기간, 이용 조건이 붙어 있다. 코드를 읽지 않고 고를 수 있다.
- **플랫폼이 먼저 제안한다**: 에이전트가 처음부터 쓰지 않고, 플랫폼이 낸 후보에서 고른다. 결정이 작을수록 실수가 적다.
- **고칠 방법이 적힌 오류**: "항목 ID 키 `id`가 없다. 후보: `nttId`, `seq`"처럼.
- **초안과 미리보기는 공짜**: 등록 전에는 아무것도 남지 않는다. 등록한 출처도 소유자가 지울 수 있다.
- **사람에게 보일 문장을 같이 돌려준다**: "이 게시판에서 글 20개를 찾았습니다. 최근 글: …. 맞나요?" 에이전트는 이 문장을 그대로 보여 주고 답을 받는다.

같은 흐름에 사람용 화면(주소 붙여 넣기 → 미리보기 → 확인)을 얇게 얹을 수 있다. **흐름은 하나, 앞단이 둘이다.**

## 2. 한 장의 모양

기업마당(운영자가 등록한 검증된 출처):

```yaml
id: bizinfo
title: 기업마당 지원사업 공고
status: verified              # verified(운영자 검토) | private(등록한 사람만)
owner: platform
connector: {kind: code, adapter: bizinfo}      # 운영자 출처는 코드 어댑터
fetch: {every: 6h, rate: 1/s}
item:
  id: pblancId
  title: pblancNm
  url: pblancUrl
keys:                          # 앱이 고를 수 있는 키. 설명과 예시는 에이전트가 읽는다
  pblancNm:   {about: 공고 제목, example: "2026년 …"}
  bsnsSumryCn: {about: 사업 개요(HTML)}
  trgetNm:    {about: 지원 대상}
  reqstBeginEndDe: {about: 신청 기간, example: "2026-10-13 ~ 2026-11-07"}
  …
meta: {apply_start: reqstBeginEndDe 앞 날짜, apply_end: reqstBeginEndDe 뒤 날짜}
ignore:
  keys: [inqireCo, updtPnttm]                  # 바뀌어도 변경이 아닌 값
  url_params: [downloadToken]
  learned: []                                  # 플랫폼이 자동으로 찾아 운영자가 승인한 것(5장)
group: repost_title            # 같은 사업 묶기: 기관이 같고 정정 표시를 뺀 제목이 같으면
attachments: {names: fileNm, urls: flpthNm, hosts: [www.bizinfo.go.kr]}
terms: {license: 공공누리 3유형, quote_limit: 300}   # 원문 노출 한도(자)
history: {since: 2026-10-23, gaps: 13}         # 미리 돌려 보기 때 함께 보인다
```

```yaml
fetch: {every: 6h, rate: 1/s}

history: {since: 2026-11-17, gaps: 0}
```

## 3. 커넥터 종류

| 종류 | 사람·에이전트가 줄 것 | 플랫폼이 알아내는 것 | 1차 |
|---|---|---|---|
| `rss` | 피드 주소 | 항목, 제목, 날짜, 링크 | 받는다 |
| `html_list` (게시판) | 목록 페이지 주소 | 되풀이되는 글 목록의 위치, 제목·날짜·링크 칸, 다음 쪽 | 받는다 |
| `file_drop` | 새 판을 올린다(파일, 나중에 메일) | 판의 순서 | 받는다 |
| `data_go_kr_list` (공공데이터포털 목록 API) | 서비스 주소, 인증키 | 목록 경로, ID 키 | 운영자만(인증키 보관이 금고 뒤에 있어야) |
| `code` (어댑터) | — | — | 운영자만 |

1차에서 받지 않는 것: 로그인이 필요한 페이지, 자바스크립트로 그리는 페이지, 앱 전용 API.

## 4. 등록 흐름 (MCP 도구)

```text
1. find_sources(query | url)   이미 있는 출처를 먼저 찾는다. 있으면 그것을 쓴다(과거 기록이 있다)
2. probe_source(url)           플랫폼이 한 번 받아 종류를 알아내고 초안 + 표본 5건 + 사람에게 보일 문장을 낸다
3. preview_source(draft)       조금 간격을 두고 두 번 받아 비교한다: 호출마다 바뀌는 값을 찾아 무시 목록 후보로,
                               항목 수, 이 출처에서 "변경"이 어떻게 보일지
4. (사람 확인)                 미리보기 문장과 이용 조건을 보여 주고 답을 받는다
5. register_source(draft)      나만 쓰는 출처(private)로 수집을 시작한다. 기록 n일을 함께 보인다
6. (승격)                      여러 앱이 쓰면 운영자가 검토해 공개 카탈로그(verified)로 올린다
```

- `html_list`의 목록 위치를 플랫폼이 찾지 못하면, 에이전트가 HTML을 보고 위치를 제안하고 플랫폼은 검증만 한다.
- 같은 주소를 두 사람이 등록하면 하나로 합친다(수집은 한 번).

**2026-11-27 1차(RSS)**: `sources/rss.py`(커넥터), `user_sources.py`(등록부, 표 `user_source`, 마이그레이션 0018), `source_tools.py`(도구).
- 도구: `find_sources`(검증된 출처 + 내가 등록한 출처), `probe_source(url)`(한 번 받아 초안·최근 글·사람에게 보일 문장, A), `register_source(draft)`(이용 조건 동의라 늘 사람의 확인, C·confirm). 3번의 미리보기(두 번 받아 비교)는 아직 없다.
- 등록한 출처는 나만 쓴다(private). 앱 정의를 검사할 때 그 사람의 출처만 더하므로 다른 사람의 앱은 쓸 수 없다.
- 수집(`scripts/snapshot.py`)은 등록된 피드를 운영자 출처와 함께 받는다(초당 1회). 적재는 등록부의 장으로 바꾸고, 기관이 없어 글 하나가 항목 하나다(다른 출처의 항목과 묶이지 않는다).
- 사용자 출처 id는 영문 소문자·숫자·`_`만(앱 정의의 `sources`가 그 모양만 받는다). 첨부는 아직 받지 않는다.

## 5. 모든 출처에 똑같이 붙는 것

에이전트가 크롤러를 직접 짜는 것과의 차이는 여기서 나온다.

- 재시도, 속도 제한, 서킷 브레이커, 수집 빈틈 기록
- **형식 변화 감시** (`drift.py`, 구현됨): 한 번의 수집에서 항목 10개 넘게, 비교한 항목의 절반 넘게 같은 키가 바뀌거나(changed), 비거나(emptied), 새로 채워지면(filled), 변경으로 넘기지 않고 마지막으로 본 값을 이어 둔다(붙잡기). 붙잡은 키는 작업 상태에 보이고, 운영자(사용자 출처면 소유자)가 고른다.

  | 상태 | 뜻 |
  |---|---|
  | held | 붙잡고 결정을 기다린다 |
  | ignored | "이 키의 변화는 보지 않는다". 계속 이어 두고 보고하지 않는다 |
  | released | "진짜 변경이다". 다음 적재 한 번은 값을 그대로 받고 closed가 된다 |
  | recovered | 값이 대부분(90% 넘게) 예전으로 돌아와 저절로 풀렸다 |

  결정은 `scripts/drift.py`로 한다. 세 번 넘게 이어서 붙잡힌 changed 키는 호출마다 바뀌는 값일 수 있다고 알려 준다(무시 후보).
- **아직 없는 결정: 받아들이기(rebase)**. 출처가 키의 형식을 바꿨고(예: 날짜 표기) 앱이 그 키를 읽는다면, 새 값을 기준으로 삼되 정정 알림은 내지 않아야 한다. 지금은 무시(값을 잃음)나 풀기(대량의 가짜 정정) 둘뿐이다. 앱이 읽는 키 기준으로 변경을 거르게 되면(app-spec 13장의 3번) 앱이 안 읽는 키는 풀어도 문제가 없으므로, 그 뒤에 만든다.

**실제 기록으로 확인 (2026-11-18, `scripts/drift_scan.py`)**: 2026-10-23~11-18의 수집 22번을 처음부터 다시 훑었다.

| 실행 | 잡힌 것 | 무엇이었나 |
|---|---|---|
| 10/30 ~ 11/16 (5번) | `bizinfo.flpthNm`, `printFlpthNm` changed, 전 항목 | 첨부 주소의 내려받기 토큰. 어댑터가 토큰을 떼기 전의 원본으로 봐도 잡힌다(`--raw`). 다섯 번 이어져 무시 후보로도 뜬다 |
| 11/17 10:39 | `kstartup.aply_excl_trgt_ctnt` emptied 75/75 | 신청 제외 대상이 한꺼번에 빔 |
| 11/17 16:34 | `kstartup.eval_method` filled 196/196, `support_ctnt` filled 145/145 | **출처가 새 항목 두 개를 보내기 시작했다.** 앞서 "글은 그대로인데 버전만 생긴 200개"의 원인이다 |
| 나머지 14번 | 없음 | 엉뚱하게 잡힌 것이 없다 |

따옴표 표기(`&apos;` → `'`) 사건은 표기 정규화가 먼저 흡수해서 여기서는 변화로 보이지 않는다(맞는 동작이다).
- 첨부 받기와 격리 파싱, 표기 정규화
- 이용 조건에 따른 노출 한도(화면, MCP 도구, 알림 본문)
- 받은 글은 신뢰할 수 없는 입력(A)으로 다룬다(하네스)

## 6. 안전

- 사설·내부 주소, 클라우드 메타데이터 주소, 표준이 아닌 포트를 막는다. 다른 주소로 넘겨도(리다이렉트) 다시 검사한다(첨부 받기의 `check_url`과 같다).
- 사용자 출처는 수집 주기 하한(예: 1시간)과 사이트당 동시 1개, 초당 1회를 넘지 못한다.
- robots.txt를 따르고, 이용 조건 동의를 기록한다.
- 사용자 출처는 소유자의 앱만 쓴다. 공개는 승격 뒤에만.
- 2026-11-27 구현: http·https와 표준 포트만. IP를 바로 쓴 주소는 직접, 이름은 풀어서 공개 주소(`is_global`)가 아니면 막는다(사설·루프백·링크 로컬·예약에 CGNAT 100.64.0.0/10까지. 알리바바 클라우드 메타데이터 100.100.100.200이 여기다. IPv4를 담은 IPv6도 풀어 본다). 넘겨주기마다 다시 보고(3번까지), 연결된 주소도 본문을 읽기 전에 다시 본다(DNS 리바인딩). 피드는 2MB·60초까지, DOCTYPE·ENTITY 선언은 바이트가 아니라 파서로 찾아 거절한다(UTF-16으로 돌아가지 못하게).
- 수집: 장의 `every_hours`보다 자주 받지 않는다. 사용자 출처의 실패는 운영자 알림·종료 코드에 넣지 않는다. 글 하나를 바꾸지 못해도 나머지 글은 받는다. 피드는 최근 몇 개만 보여 주므로 빠진 글을 닫지 않는다.
- 같은 피드를 다른 사람이 등록하면 겹치지 않는 id(`_2`)를 제안한다. 같은 주소를 하나로 합치기(4장)는 아직이다.

## 7. 지금 코드와의 관계

| 지금 | 카탈로그에서 |
|---|---|
| `sources/bizinfo.py`, `sources/kstartup.py` | `connector: {kind: code}` |
| `sources.base._VOLATILE`, `stable_url`의 `downloadToken`, 스냅샷의 `updtPnttm` | `ignore` |
| `programs.api_meta`, 어댑터의 `apply_start`·`apply_end` | `meta` |
| `programs`의 재게시 묶기(`title_key`) | `group` |
| `programs.detect_drift`(한꺼번에 빔) | 형식 변화 감시의 일부(5장) |
| `sources.attachments.check_url` | 안전(6장) |
| 실행 기록(`runs/`), 수집 공백 | `history` |

**2026-11-24 코드로 옮김**: 규격은 `catalog.py`(공개 스키마 `docs/source-schema.json`), 운영자 출처 두 장은 `src/noticedelta/sources/catalog/bizinfo.json`, `kstartup.json`이다. 어댑터는 무시할 키, 첨부 주소 키, 떼는 주소 값, 받아도 되는 호스트를 이 장에서 읽는다(옮기기 전과 값이 같은지 시험이 본다). 앱 정의의 검증은 카탈로그에서 출처, 읽을 수 있는 키(무시하는 키는 뺀다), 구조화 값(`meta`)을 받는다. 위 예시와 다른 점:

- `fetch`는 `every_hours`, `rate_per_second` 숫자로 적는다(문자열 "6h"를 풀지 않으려고).
- 주소를 새로 발급하는 키는 `ignore.url_keys`에 적는다(위 예시의 `attachments.urls`와 겹치지만 뜻이 다르다. 첨부 주소라도 새로 발급하지 않는 출처가 있다).
- `connector.kind`는 `code`(운영자)와 `rss`(사용자, 2026-11-27)를 받는다. html_list·file_drop은 아직이다.
- 키마다 `about`(설명)을 적고, 출처가 보내는 키가 모두 설명되어 있는지 시험이 본다(받은 응답 견본 기준). 예시 값은 원문 인용이 되므로 넣지 않았다.
- `history`(수집 기록)는 장에 적지 않고 실행 기록에서 계산한다.

## 8. 열린 질문

| 질문 | 초안의 선택 |
|---|---|
| 사용자가 준 인증키(공공데이터포털 등)를 어디에 둘까 | 개인정보 금고(B). 그 전까지는 운영자만 |
| 형식 변화로 붙잡은 변경을 누가 풀까 | 운영자 출처는 운영자, 사용자 출처는 소유자(미리보기와 함께) |
| 사용자 출처의 과거 기록이 짧을 때 미리 돌려 보기 | 기록 n일을 함께 보이고, 모자라면 가상 변경으로 |
| `html_list`의 위치 표현 | CSS 선택자. 플랫폼이 제안하고 검증한다 |
